# Full-stack Notes application

This project is a small notes application with:

- **Frontend:** React 18, Vite, Axios
- **Backend:** Node.js, Express, Mongoose
- **Database:** MongoDB (local MongoDB or MongoDB Atlas)

The browser talks to the Express API. The Express API talks to MongoDB. The
browser does **not** connect directly to MongoDB.

## Project structure

```text
.
├── backend/
│   ├── index.js              # Express server and API routes
│   ├── models/note.js        # Mongoose Note model
│   ├── .env                  # Local secrets; do not commit this file
│   └── package.json
├── frontend/
│   ├── src/App.jsx           # React UI
│   ├── src/services/notes.js # Frontend API calls
│   ├── vite.config.js        # Development proxy for /api
│   └── package.json
└── README.md
```

## Prerequisites

Install the following before starting:

1. **Node.js** (the current project works best with Node 22; Node 20 or newer
   should also work).
2. **npm** (included with Node.js).
3. A MongoDB database:
   - **MongoDB Atlas** is easiest if you do not want to install MongoDB locally.
   - **MongoDB Community Server** works locally.

Check Node and npm:

```powershell
node --version
npm --version
```

## 1. Get the project ready

Open PowerShell in the project directory:

```powershell
Set-Location "C:\path\to\front and back stack"
```

Install dependencies separately for the backend and frontend:

```powershell
Set-Location ".\backend"
npm install

Set-Location "..\frontend"
npm install
```

Do not install or commit `node_modules`. It is generated by `npm install`.

## 2. Configure MongoDB

### Option A: MongoDB Atlas

1. Create a free cluster at <https://www.mongodb.com/atlas>.
2. Create a database user and password.
3. In **Network Access**, allow your development IP address. For temporary
   local learning only, Atlas also allows `0.0.0.0/0`, but this is less safe.
4. Select **Connect > Drivers**, choose Node.js, and copy the connection
   string.
5. Replace the username, password, and database name in the connection string.

### Option B: Local MongoDB

Install and start MongoDB Community Server, then use a local URI such as:

```text
mongodb://127.0.0.1:27017/notes
```

### Create `backend/.env`

Create a file named `.env` inside `backend`:

```env
MONGODB_URI=mongodb+srv://<username>:<password>@<cluster-host>/notes?retryWrites=true&w=majority
PORT=3001
```

For local MongoDB:

```env
MONGODB_URI=mongodb://127.0.0.1:27017/notes
PORT=3001
```

Keep the real URI and password private. Never paste credentials into source
files or commit `backend/.env`. If a MongoDB password contains characters such
as `@`, `:`, `/`, or `#`, URL-encode it before putting it in the URI.

## 3. Start the backend

Open a PowerShell window:

```powershell
Set-Location "C:\path\to\front and back stack\backend"
npm run dev
```

`npm run dev` starts Node's watch mode. The server connects to MongoDB first
and then listens on `http://localhost:3001`.

For a normal (non-watch) start:

```powershell
npm start
```

A successful startup prints:

```text
Server running on port 3001
```

If the backend exits with `Could not connect to MongoDB`, check the URI,
database user/password, Atlas network access, and whether local MongoDB is
running.

## 4. Start the frontend

Keep the backend window running and open a second PowerShell window:

```powershell
Set-Location "C:\path\to\front and back stack\frontend"
npm run dev
```

Open the URL printed by Vite, normally:

```text
http://localhost:5173
```

The frontend's `vite.config.js` proxies every `/api` request to
`http://localhost:3001`. This means the React code can call `/api/notes`
without hard-coding the backend host or configuring a separate frontend
environment variable during development.

## How frontend and backend connect

The request path is:

```text
React UI
  -> Axios in frontend/src/services/notes.js
  -> /api/notes
  -> Vite proxy (development only)
  -> Express at http://localhost:3001
  -> Mongoose
  -> MongoDB
```

The frontend sends these requests:

| Action            | HTTP request            | Purpose                       |
| ----------------- | ----------------------- | ----------------------------- |
| Load notes        | `GET /api/notes`        | Return all notes              |
| Create note       | `POST /api/notes`       | Save `{ content, important }` |
| Change importance | `PUT /api/notes/:id`    | Update a note                 |
| Load one note     | `GET /api/notes/:id`    | Return one note               |
| Delete note       | `DELETE /api/notes/:id` | Delete a note                 |

Example create request:

```http
POST http://localhost:3001/api/notes
Content-Type: application/json

{
  "content": "Learn how the API works",
  "important": true
}
```

The backend converts MongoDB's `_id` to `id` in JSON so the frontend can use
`note.id`.

## API error handling

The backend returns JSON errors with an `error` property where possible:

- `400` - missing note content or malformed MongoDB ID
- `404` - note or endpoint does not exist
- `500` - unexpected server/database error

The React app reads `error.response.data.error` and displays a notification.
For a failed update, it removes the note from the local list because the note
may already have been deleted on the server.

When debugging an error:

1. Check the browser Developer Tools **Network** tab.
2. Check the backend PowerShell window for the server-side error.
3. Test the API directly:

```powershell
Invoke-RestMethod -Uri "http://localhost:3001/api/notes" -Method Get
```

Create a note directly from PowerShell:

```powershell
$body = @{
  content = "API test"
  important = $false
} | ConvertTo-Json

Invoke-RestMethod `
  -Uri "http://localhost:3001/api/notes" `
  -Method Post `
  -ContentType "application/json" `
  -Body $body
```

## Backend linting

The backend uses ESLint with a flat configuration in
`backend/eslint.config.mjs`. ESLint is installed as a development dependency
because it is a development-time code-quality tool and is not required to run
the production server.

Run the linter from the backend directory:

```powershell
Set-Location ".\backend"
npx eslint index.js   # check one file
npm run lint          # check the backend project
```

The backend configuration:

- uses Node globals and CommonJS module syntax;
- ignores generated files in `backend/dist`;
- enables ESLint's recommended rules;
- requires strict equality with `===` and `!==`;
- checks indentation, Unix (`LF`) line endings, single quotes, and no
  semicolons;
- checks trailing spaces, object-brace spacing, and arrow-function spacing;
- allows `console.log` for server logging.

The VS Code ESLint extension can display these problems directly in the
editor. When the line-ending rule reports an error on Windows, save the file
with `LF` line endings using the line-ending selector in VS Code's status bar.

The old `frontend/db.json` and `npm run server` command belong to the earlier
JSON Server version of the exercise. The current application uses the
Express/MongoDB backend instead, so you normally do not need to start JSON
Server.

## Production build note

`npm run build` in `frontend` creates `frontend/dist`. The Express server serves
a `dist` directory relative to `backend`, so a deployment that serves the
frontend from Express must copy the built files into `backend/dist` (or use a
separate static hosting service for the frontend). In production, configure
the frontend host and backend CORS/proxy settings for the deployed domains
instead of relying on Vite's development proxy.

## Troubleshooting

### `MONGODB_URI is not set`

Make sure the file is exactly `backend/.env`, the variable is exactly
`MONGODB_URI`, and the backend is restarted after changing it.

### MongoDB authentication or network error

Verify the Atlas database user, URL-encoded password, IP allowlist, and
connection string. For local MongoDB, verify the MongoDB service is running
and use `mongodb://127.0.0.1:27017/notes`.

### Browser shows a network/CORS error

Start the backend on port 3001 and the frontend through Vite on port 5173.
Use frontend requests beginning with `/api`, not a direct MongoDB URL. The
backend enables CORS for development, while Vite forwards `/api` requests.

### `404` from the frontend

Confirm that the backend is running and that the browser request is going to
`/api/notes`. If you are using a production build, configure the production
web server to forward `/api` to Express; the Vite proxy only exists during
development.
